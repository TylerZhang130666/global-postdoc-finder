# 按任务使用

共用的资格、评分和隐私规则见 `SKILL.md`；本页补充单条核验、搜索覆盖、清单更新与申请准备。

## Single-lead verification

用户只给一条招聘信息时，先核验这条信息，不要求完整CV，也不自动扩大成全球搜索。

1. 读取用户提供的链接、原文或可辨认的截图。把原帖说法与助手指令分开；不能读取的图文说明限制，不能把猜测当OCR结果。截图裁切可能丢失轮次、年份或雇主，先保留未知。
2. 提取可检索的机构、岗位标题、岗位编号、领域与日期；找实际雇主或基金官方公告。招聘平台中的雇主链接可以作为路径，社交账号、自称“官方”的标题和搜索摘要不能单独证明来源。
3. 逐项比对雇主、机会类型、岗位编号、当前状态、轮次/阶段、截止日期、资格、薪酬与申请入口。不同年份的同名项目不能混用。机构/PI介绍页、项目获资助、Hosting意向均不能证明有现成岗位。
4. 通过公告指向的入口核实申请路径。可只读打开表单，记录“表单可读/后续需注册/未测试提交”。不以网页可达、Apply按钮或一般首页代替开放证据；明确关闭优先于残留按钮和未来日期。
5. 用[核验模板](../assets/lead-verification-template.md)给出证据、冲突、未知与下一步。保留日期原文和精度；没有官方时间/时区就不从聚合页补成精确倒计时。未找到官方公告只能说未确认，不能直接判假。

没有候选人背景时，仅判断招聘信息，不计算个人资格或匹配分。若背景已知，可接着按筛选规则判断，并把“岗位当前开放”和“这个人可以申请”分开。只有相关要求确实需要时才补问个人事实。

## Search coverage

每次联网搜索/核验都输出一份简洁覆盖表；需要保存时从[JSON空模板](../assets/search-coverage-template.json)开始。

`channels`每项包含：`source_id`（目录ID或本次自定义雇主ID）、`source_url`、`regions`、`opportunity_types`、`status`、`search_terms`、`date_checked`、`retained_record_ids`、`reason`。`reason`记录没有保留结果的依据或访问限制，不保存含私人资料的查询。`gaps`列请求范围内尚未覆盖的地区/类型及原因。

| status | 含义 |
|---|---|
| `not_searched` | 本次没查；`date_checked`留空。不能写“没有结果”。 |
| `searched_no_retained_results` | 执行了记录的查询，但没有保留合适记录；注明未找到相关结果，还是找到后因何筛掉。不能推广为整个渠道没有岗位。 |
| `searched_retained_results` | 完成记录的查询，保留了相关记录；列出记录ID。 |
| `partial` | 仅首页/部分页面/索引可读，搜索、分页或详情未能完成；即使保留线索也须说明限制。 |
| `inaccessible` | 尝试访问所需入口但未读到内容；记录错误或登录限制。403不自动等于必须登录。 |

每个渠道记录实际关键词、过滤和日期；分页或详情未查完用`partial`。仅在站外搜索过某站点，不写成完成了站内检索。目录维护的`access_status`表示上次访问检查，不能直接复制为本次搜索状态；未测试的目录项保持`not_searched`或不纳入本次计划。报告至少列出实际尝试的渠道、计划但未查的重点渠道和地区缺口，无需为不相关的整个来源库制造清单。

“全球首轮”应按已请求的各地区说明做到哪一步；明确没有覆盖的部分。单条信息核验只需解释该公告的证据链，不为它扩展无关地区。离线回放明确标为离线，不生成虚假的联网覆盖日志。

## Saved-list refresh

1. 读取旧快照日期、范围、候选人假设和判断。保留原文件；只有旧表而缺少证据时注明无法还原。先复核临近截止、已选中和待核实的条目，再按用户范围补搜新增机会。
2. 在新快照记录真实核查日期、官方链接、条件和变化依据。没有重访或搜索中未再出现的条目记为“未重新确认”；网页打不开也不能单独证明关闭。旧截止日期推算的过期与本次官方明确关闭分开说明。
3. 使用稳定的雇主与招聘编号，或足够具体的官方公告URL对齐记录。`record_id`常是某次运行内的编号，编号变动不代表新增。招聘首页共享URL、标题变体、不同轮次、岗位类型或雇主冲突需要人工核实，不能自动合并。
4. 可用下面的离线辅助脚本生成差异，再人工审阅。它只比较输入，不能联网复核或证明记录属于同一招聘。

```text
python scripts/diff_records.py previous.json current.json --as-of 2026-11-18 --out changes.json
```

输入为JSON记录列表；兼容评分脚本字段，可增加 `employer_id` 与 `canonical_notice_id` 以提供稳定身份。输出保留前后记录、匹配依据、条件变化、判断变化、批内重复和待人工确认项。匹配细则与状态含义以脚本及返回的`reason`为准。局部复核的结果不能当作全清单已更新。

向用户分别说明：**新发现、同一机会再次找到、官方条件变化、确认关闭、未重新核实、身份待复核**。评分/行动等级变化单列原因，区分官方条件变化、候选人补充事实和规则修订；不把模型重新打分当作雇主变更。若新旧快照使用不同画像、范围或规则，先解释可比性。将已确认的字段、旧值、新值与来源日期一同保留，不覆盖历史判断。

## Application preparation

先重新核实选定机会及其阶段，再给出这张对照表：

| 招聘要求及来源位置 | 必需/优先/未说明 | 我的现有证据及材料位置 | 状态 | 待补材料或问题 | 下一步 |
|---|---|---|---|---|---|
| 用公告原意概括 | 不擅自把优先改成必需 | CV条目/论文状态/项目证据；没有则未知 | 已支持/部分支持/未知/确认冲突 | 只写真正缺少的证明 | 先补证据、询问或起草 |

按截止日期和阻塞性优先准备学位/时间、方法与成果、语言、阶段/接收导师、表单所需文件。区分公告列出的材料、表单可见必填项与助手建议材料。可根据此表起草简历要点、动机信或咨询邮件，保留缺失事实占位，不夸大相关领域经验；不得把draft当成已提交。联系雇主、注册、上传和提交需单独的明确授权。
